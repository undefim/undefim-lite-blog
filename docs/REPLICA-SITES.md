# 独立受管子站

本功能取代早期“一主一从、同域名、推送 release”的设计。主站继续使用原有 Dockerfile、compose.yaml、管理员与数据库；子站使用独立的 [Dockerfile.replica](../Dockerfile.replica) 与 [compose.replica.yaml](../compose.replica.yaml)，不是 `SITE_ROLE=replica` 模式，不需要 WireGuard、SSH 推送或网页初始化向导。

## 管理流程

1. 在主站后台打开“子站”，填写名称、主站域名、子站域名。主站地址默认当前浏览器 origin，可修改；使用 HTTPS 公网地址，域名不带路径。
2. 点击“生成部署命令”。认证码由主站生成，只显示一次、24 小时过期、成功接入后失效。数据库仅保存哈希。命令及 `.env` 在接入前都包含有效凭据，不能公开、截图、粘进工单或提交；泄露时立即重新生成认证码。
3. 在新子站 VPS 的空目录执行生成的命令。VPS 需要 Git、Docker Engine 和 Compose v2；从固定 GitHub 仓库克隆并构建子站镜像及更新执行器。主站提交已知时命令固定到该提交，并写入 APP_REVISION；如果该提交尚未推送到仓库，部署会失败而非静默使用其他版本。不能在主站目录或已有正式数据目录执行。
4. 子站主动向主站接入、保存长期凭据，定期拉取主站专门为它构建的版本。主站无需连接子站的入站端口。
5. 为子站域名设置 DNS、TLS 和反向代理到 `127.0.0.1:4322`，参考 [nginx-replica.conf](../deploy/nginx-replica.conf)。**生成命令不自动申请证书、不配置 DNS、不安装 Docker。**
6. 主站后台查看通信、内容同步、程序版本及更新状态。程序和内容是两个独立版本：内容构建不更新程序，程序更新不发布草稿。

子站镜像没有 npm 依赖、Astro、SQLite 或管理后台。它仍使用 Node 运行时；更新执行器还包含 Git、Docker CLI 和 Compose，不能把整个部署的体积等同于子站应用镜像体积。

## 文章范围与外观

- “显示全部”：选中项表示排除；以后新文章默认显示。
- “仅显示选中”：选中项表示允许；以后新文章默认不显示。
- 范围针对文章（post）；已公开的自定义页面始终保留。私密、草稿、回收站内容不作为子站正文源。
- 每个子站可以独立覆盖：Dream/窑火风格、站点标题、描述、公告、顶部导航、ICP 备案号、公安备案号。
- 未启用自定义的项目继承主站的已发布设置；自定义备案信息留空代表不显示，不是继承。暂不支持任意 HTML 页脚或任意脚本。
- 文章规则和外观设置保存后排队构建；成功同步后才生效。主站设置保存但未发布时，不应被当作已发布的子站配置。
- canonical、RSS、网站地图按子站自己的域名构建。更换子站域名还需维护者调整 DNS、TLS、代理。

## 构建与同步

主站从 `current/content.json` 读取实际已发布快照，为各子站过滤文章并覆盖公开设置，使用子站 `SITE_URL` 运行 Astro。主站发布与子站构建共用单进程串行队列，不新增第二个写实例。子站数量越多，构建队列越长；单个子站失败保留原版本，不使已经成功的主站发布回退。

主站文件位于私有 `data/replica-builds/<子站ID>/<构建ID>/`；它不在静态公开目录中。子站通过独立凭据获取属于自己的当前有效清单、文件与公开媒体。规则或主站源版本改变时旧产物下载会被拒绝；构建中再次改规则会丢弃过时产物。子站先准备媒体与 `.partial` 目录，再验证文件并通过相对符号链接切换 `current`；未完成版本不会上线。断网期间继续提供上一个静态版本，评论依赖主站连接。

媒体仍是公开资源：文章筛选不是媒体访问控制。不能宣称被排除文章的附件变成私密。已经下载到子站或浏览器/CDN的内容也无法通过吊销凭据远程收回；下线需等待构建同步，并按需要清除缓存。

子站本地凭据 `data/replica.json` 必须保护（文件模式 0600），不得公开挂载 data。服务器更换时需要重新生成认证码；不要复制主站完整备份去初始化子站。

## 评论、计数与更新

浏览器同源调用子站 `/api/public/*`，子站程序转发到主站；主站保存评论、审核状态与访问/点赞计数。访客统计 `POST /api/public/pageview` 同样转发（只转发 `bvid` 等交互 Cookie），主站凭子站凭据把记录归属到该子站，并以子站域名判断站内跳转，按子站上报的读者 IP 在主站判断国家/地区（子站不需要 IP 库）；后台“访客”页按主站和每个子站分别显示。子站 `/admin/` 跳转主站，不提供本地管理账号。代理必须覆盖外部传入的客户端 IP 头；主站仅对有效子站凭据接受子站报告的访客地址。

“更新子站程序”把主站当前提交作为目标，由子站领取后交给其本地 updater。执行器从部署固定的 GitHub 仓库、分支获取代码，验证目标提交属于跟踪分支，只允许快进，拒绝任意命令、远端仓库和分叉覆盖。子站 updater 不执行本地定时自动升级，只处理显式任务；子站程序容器不能挂 Docker socket；只有执行器可以访问它，该执行器拥有高权限，主站账号、子站凭据和 GitHub 仓库均须保护。

子站模式用 `UPDATE_MODE=replica`、`compose.replica.yaml`，没有主站数据库备份与 `application-revision` 检查；保留本地凭据与静态版本，更新失败尝试恢复旧镜像和源码。更新执行器自身运行环境变化仍需人工部署，不能承诺所有宿主机管理操作都能在主站后台完成。

## 数据库升级与回退

[replica-migrations.mjs](../server/replica-migrations.mjs) 在事务中创建 `replica_schema_migrations`（版本 1）、`replica_sites`、`replica_documents`，不改旧正文、版本、账号等表。已存在的受支持开发期子站表通过显式 `ALTER TABLE` 补 `settings`；未知原型结构报错并回滚，禁止自动删表重建。

上线前按现有备份流程做完整备份并验证可恢复。升级后检查 `PRAGMA integrity_check`、`PRAGMA foreign_key_check`、迁移版本和管理员登录；再用独立测试子站验收。原版程序会忽略新增表，回退代码无需删除它们；不要为了回退而恢复旧整库覆盖新文章。停止子站 updater/同步并撤销凭据后再回退，避免孤立任务。必要时由维护者在备份与停写条件下单独清理新表。

## 运维限制与验收边界

- 先把功能合入可拉取的固定分支并部署主站，再使用部署命令；未推送的本地代码不可能由 VPS 克隆到。
- 不支持多个主站写实例、自动主站故障切换或多主合并。
- 子站同步是最终一致，不是两台机器同时原子上线。确认子站已同步后再判断撤回完成。
- 子站域名的 CDN 清除尚未集成，应单独配置 HTML 缓存策略，敏感下线手动清除缓存。
- Docker、TLS、真实 VPS 更新与回退必须在对应环境验收，Node 集成测试或命令替身测试不等同于真实容器验收。

### 同步失败处理

失败的子站构建可在后台“重新构建”重试；主站重启或下次发布也会重新检查失败状态。没有承诺离线已下载内容可远程擦除。更换认证码后已有服务器若仍保存旧长期凭据，需要在维护窗口移走其私有 replica.json，再使用新码重新接入；保留原文件作为受保护回退副本。升级执行器或 Docker/防火墙仍是宿主机维护操作。
